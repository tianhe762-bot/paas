# PAAS — 个人消费自动记账系统

> 把记账变成聊天：在 QQ 或 Telegram 里直接发一句话，账单自动进账、自动分类、自动算余额。

PAAS（Personal Auto Accounting System）是一款部署在自己服务器上的个人记账机器人。核心思路是**用自然语言聊天完成记账**：你发一句"今天微信吃饭花了25"，系统自动识别时间、账户、分类、金额并写入 SQLite 账本；你说"删除刚才那笔""这个月花了多少""微信还有多少钱"，它都能听懂并正确执行。所有数据只存在你自己的服务器上，不经过任何第三方记账云端。

## 核心功能

- **自然语言记账**：多笔拆分（"今天中午吃火锅花了86，打车回家23块"）、中文数字（"三十五""二十多""一百二"）、相对日期（"昨天""前天""大前天"）、具体日期（"8月25号"）。
- **四种账单类型**：支出、收入、转账（含手续费）、退款，另有独立统计的"平账调整"。
- **多账户管理**：微信 / 支付宝 / 银行卡 / 现金 / 信用卡，每账户独立余额；支持设置初始余额。
- **多机器人多用户**：QQ 与 Telegram 各支持最多 5 个机器人，每个机器人账本完全隔离；管理员可管理所有人，普通用户只能管理自己的机器人。
- **缺失信息询问**：缺账户问账户、缺时间问时间，绝不瞎猜。
- **历史补记**：过几天补记某一天的账单，按你说的日期入账。
- **删除与修改**：撤销（软删除，保留历史）与修改金额，余额自动同步。
- **平账对账**："微信平账到90元"，自动算差额、二次确认、独立统计。
- **查询与报表**：单账户余额、总资产、今日/昨日/本周/上周/本月/上月/自定义日期范围的收支与分类统计，支持"详细一点"。
- **账本导入**：直接发 Excel/CSV 文件（微信支付、支付宝、钱迹、随手记、鲨鱼记账等导出均可），自动识别关键列、排除昵称/单号等垃圾信息。
- **数据导出**：管理界面下载 CSV / XLSX 完整账本。
- **防重复与防抖**：同一消息重发直接拒绝；30 秒内相同消费二次确认，不会重复记账。
- **定时提醒与备份**：默认 21/22/00 点提醒记账；每日 SQLite 热备份并保留 30 天。

## 架构

```text
QQ 官方机器人 ──┐
                ├──→ PAAS（Docker 容器）──→ 机长（命令路由）──→ 记账模块 ──→ SQLite 账本
Telegram Bot ───┘                 │                         │
                                  ├── 管理界面（网页 /admin）   └──→ 热备份 / 导出 / 导入
                                  └── 可扩展：System / Proxy / Docker / NAS 等模块
```

- 通信层与业务层完全解耦：QQ 走官方 OpenAPI（AppID + AppSecret，WebSocket 直连，无需中转服务），Telegram 走 Bot API 长轮询。
- 金额一律以「分」为整数存储（`amount_cents`），数据库无浮点误差。
- 管理员密码只保存 scrypt 哈希；机器人密钥用 `SECRET_KEY` 加密后落库，数据库内无明文。

## 快速开始（Docker 部署）

### 环境要求

- 一台 Debian 12 / Ubuntu 22.04+（或其他 Linux），已安装 Docker 与 Compose：

```bash
docker --version
docker compose version
```

### 部署步骤

1. 获取项目代码并进入目录：

```bash
git clone <你的仓库地址> paas && cd paas
```

2. 创建配置文件：

```bash
cp .env.example .env
vi .env
```

必改项：

| 变量 | 说明 |
|---|---|
| `API_KEY` | 入站 API 鉴权密钥，用 `openssl rand -hex 24` 生成，至少 32 位 |
| `ADMIN_PASSWORD` | 管理界面初始密码（至少 8 位，首次启动后建议立即在界面里改） |
| `SECRET_KEY` | 密钥加密密钥，用 `openssl rand -hex 32` 生成；不设置会自动生成到 `data/secret.key`（删掉会导致已存机器人密钥无法解密） |

3. 准备数据目录（容器内以 uid 1000 运行）：

```bash
mkdir -p data logs && chown -R 1000:1000 data logs
```

4. 构建并启动：

```bash
docker compose up -d --build
docker compose logs -f paas        # 查看启动日志
```

5. 打开管理界面：`http://<服务器IP>:8000/admin`
   - 用 `.env` 里的 `ADMIN_USERNAME` / `ADMIN_PASSWORD` 登录。
   - 页面右上角应显示版本号（如 `v2.1`）；如仍显示旧版请按 **Ctrl+F5** 强刷。

6. 在「平台配置」里接入 QQ 或 Telegram（见下），保存并启用。

> 说明：PAAS 使用 `network_mode: host` 直接监听宿主机 8000 端口，便于走宿主机网络访问 Telegram。

### 国内服务器 Docker Hub 慢

编辑 `/etc/docker/daemon.json` 配置镜像加速后重启 Docker：

```json
{
  "registry-mirrors": [
    "https://docker.1ms.run",
    "https://docker.m.daocloud.io",
    "https://docker.xuanyuan.me"
  ]
}
```

```bash
systemctl restart docker
docker pull alpine:3.20   # 验证加速源可用
```

## 接入 QQ 官方机器人

本项目使用 **QQ 开放平台官方机器人**（q.qq.com），**不依赖 OneBot/NapCat 等中转服务**。

### 申请机器人

1. 登录 [QQ 开放平台](https://q.qq.com/) → 机器人 → 创建机器人应用。
2. 在「开发 → 开发设置」中获取 **AppID** 与 **AppSecret**。
3. 完成开发者资质认证（个人/企业），确认已开通单聊（C2C）消息权限。
4. 在 QQ 里搜索并添加自己的机器人（沙箱环境亦可先联调）。

### 在 PAAS 管理界面配置

1. 打开 `/admin` → 「平台配置」→ QQ。
2. 填写 AppID、AppSecret。
3. 点「测试连接」：验证 AppSecret 能否换取 access_token。
4. 勾选「启用」→ 点「保存」。保存后状态变为「运行中」，机器人即通过 WebSocket 连接官方网关接收消息。

## 接入 Telegram 机器人

1. 在 Telegram 里找 @BotFather，发 `/newbot` 按提示创建机器人，拿到 **Bot Token**（形如 `123456:ABC-DEF...`）。
2. 打开 `/admin` → 「平台配置」→ Telegram，填入 Token。
3. 点「测试连接」→ 应显示"连接正常：机器人 @xxx 可用"。
4. 勾选「启用」→ 点「保存」。

> ⚠️ 同一个 Token 只能有一个程序在轮询。如果你已有其他程序（例如系统监控机器人）在用同一个 Token，会报 409 冲突——请为 PAAS 单独创建一个机器人。

## 聊天命令大全

### 记账

| 输入 | 结果 |
|---|---|
| `今天微信吃饭花了25` | 支出 25 元，微信，餐饮 |
| `今天中午和同事吃火锅花了86，打车回家23块` | 自动拆成 2 笔 |
| `银行卡今天收入5000` | 收入 5000 元 |
| `微信转银行卡500元，手续费0.3元` | 转账 500 + 手续费 0.30，余额同步 |
| `支付宝今天收到退款30元` | 退款 30 元 |
| `昨天支付宝买显卡花了3999` | 补记到昨天 |
| `8月15日微信吃饭花了25` | 补记到指定日期 |
| `帮我记一下，今天微信吃饭花了25元` | 语气词自动忽略，正常入账 |

缺账户会问"使用哪个账户？"，缺时间会问"这笔消费是什么时候发生的？"，按提示回复即可。

### 删除 / 修改

| 输入 | 结果 |
|---|---|
| `删除刚才那笔` / `撤销上一笔` / `作废最后一笔` | 展示目标并请求确认，回复「是」后软删除 |
| `删除25元那笔` | 按金额定位删除 |
| `删除8月10日那笔25元` | 删除往期账单 |
| `刚才那笔不是25，是35` | 修改金额并同步余额 |
| `把刚才那笔改成35` | 同上 |

### 查询 / 报表

| 输入 | 结果 |
|---|---|
| `微信还有多少钱` | 微信当前余额（可为负） |
| `总资产` / `所有账户` | 各账户余额 + 总资产 |
| `今天` / `今天花了多少` | 今日收支与分类 |
| `昨天` / `本周` / `上周` / `本月` / `上月` | 对应周期统计 |
| `这个月吃饭花了多少` | 按分类统计 |
| `这周微信花了多少` | 按账户统计 |
| `8月1日到8月10日花了多少` | 自定义日期范围 |
| `8月15日花了多少` | 单日查询 |
| `今天详细一点` | 在统计后追加逐笔明细 |

### 平账

| 输入 | 结果 |
|---|---|
| `微信平账到90` | 计算差额（如当前 100 → 调整 -10），二次确认后入账 |
| `平账10 微信对不上` | 直接调整 10 元并附备注 |

平账属于特殊调整，**不计入消费统计**，可单独在报表的"平账调整"行看到。

### 其他

| 输入 | 结果 |
|---|---|
| `无消费` | 确认今日无消费，不再提醒 |
| `跳过` | 跳过今日记账 |
| `导入` | 提示发送账本文件 |
| `导出` | 返回流水笔数与管理界面下载地址 |
| `帮助` | 查看本说明 |
| 发送 `.csv` / `.xlsx` 文件 | 自动导入账本 |

## 管理界面说明

访问 `http://<服务器IP>:8000/admin`。

- **机器人管理**：添加/编辑/删除机器人（QQ 与 Telegram 各最多 5 个）。每个机器人有独立的名称、凭证、启用开关与账本命名空间，数据完全隔离。管理员可查看和操作所有机器人；普通用户只能看到并管理自己的机器人。删除机器人会连同其账本数据一并清除（需二次确认）。
- **用户管理（仅管理员）**：创建普通用户/管理员账号；普通用户登录后只能创建和管理自己的机器人。管理员可删除任意用户。
- **系统设置**：时区、提醒时间（默认 21,22,0）、提醒文案、防抖窗口（秒）、待确认有效期（秒）、备份保留天数、每日备份时间。
- **安全**：修改管理员密码。
- **状态与备份**：各适配器运行状态、最近错误、记账/导入笔数、立即热备份、下载导入模板、最近导入记录。

## 历史账本导入

直接把 `.csv` 或 `.xlsx` 文件发给机器人即可自动导入（QQ / Telegram 均可）。

### 支持的表头（自动识别）

| 角色 | 常见表头 |
|---|---|
| 日期 | 日期 / 交易时间 / 消费日期 / 记账日期 / date / time |
| 金额 | 金额 / 消费金额 / 支出金额 / amount / price（支持 `¥25.00` 前缀与负数收入） |
| 分类 | 分类 / 交易分类 / 类别 / category |
| 类型 | 类型 / 收支 / 收/支 / 交易类型（收入/支出/退款） |
| 账户 | 账户 / 支付方式 / 收/付款方式 / account |
| 备注 | 备注 / 描述 / 说明 / 明细 / 摘要；无备注时取"商品/商品说明" |

**垃圾信息自动排除**：微信昵称、交易对方、对方账号、交易单号、商户单号、支付状态等列不会被写入备注。

### 示例 CSV

```csv
日期,金额,分类,备注
2026-08-01,86.5,餐饮,吃火锅
2026-08-02,23,交通,打车回家
```

支持 UTF-8 / UTF-8 BOM / GBK 编码；表头不必在第一行；金额按「元」填写，系统自动转分为整数存储。管理界面可下载官方导入模板。

## 数据导出

- **管理界面下载**：`GET /admin/api/export?user_id=<用户ID>&format=csv|xlsx&start=2026-08-01&end=2026-08-31`
  - `format`：`csv` 或 `xlsx`
  - `start` / `end`：可选日期范围（`YYYY-MM-DD`）
  - 导出列：ID、日期、类型、分类、账户、金额(元)、备注、状态、原始消息
- **聊天命令**：发送「导出」查看笔数统计；完整文件请在管理界面下载。

## 数据、备份与恢复

- 所有数据在 `data/` 目录（SQLite 账本 `account.db` + 备份 `backups/` + 密钥 `secret.key`），日志在 `logs/`。
- 每日 03:00 自动热备份（SQLite 官方 `backup()` API，绝不直接拷贝运行中的 db 文件），默认保留 30 天。
- 恢复：停容器 → 用备份文件替换 `data/account.db`（同时删除 `-wal` / `-shm`）→ 启动容器。

```bash
docker compose restart paas                                  # 重启
docker compose logs -f --tail 200 paas                       # 看日志
docker compose build --pull && docker compose up -d          # 升级
```

## 安全说明

- 管理员密码：scrypt 加盐哈希存储，数据库里没有明文；`.env` 里的 `ADMIN_PASSWORD` 仅在首次启动时写入。
- 机器人密钥（QQ AppSecret、Telegram Token）：用 `SECRET_KEY` 派生 Fernet 密钥加密后落库；**请勿删除 `SECRET_KEY` 或 `data/secret.key`**，否则已存密钥无法解密。
- 入站 API：`/api/v1/message/inbound` 需要 `X-Api-Key` 请求头（`.env` 的 `API_KEY`）。
- 请勿把 `.env`、`data/`、`secret.key` 提交到 git（`.gitignore` 已默认排除）。
- 服务建议只在内网或加反向代理 + HTTPS 后暴露。

## 常见问题

### 普通用户如何注册

目前由管理员在「用户管理」页创建账号（用户名 + 初始密码 + 角色）。普通用户登录后即可添加自己的 QQ/Telegram 机器人，账本与其他人完全隔离。

### 管理界面保存失败 / 显示旧版本

先按 **Ctrl+F5** 强刷，或打开无痕窗口访问；页面右上角应显示版本号。若仍失败，把"保存失败："后面的具体文字发出来。

### Telegram 一直报 409 Conflict

同一个 Token 被其他程序同时轮询。给 PAAS 单独建一个 BotFather 机器人，或停掉另一个轮询程序。

### 机器人收不到 QQ 消息

确认已开通单聊（C2C）事件权限、机器人已通过审核/处于沙箱外可发布状态；在管理界面「状态」页查看 QQ 适配器是否运行中。

### 金额不对 / 记错账户

用 `删除刚才那笔` 撤销后重记，或用 `刚才那笔不是25，是35` 直接修改。

### 导入后某些行失败

发送「导入」后机器人会返回失败行数与原因（常见：金额/日期无法识别）。确认表头名称在支持列表内，或先用管理界面模板整理。

## 目录结构

```text
paas/
  communication/   # QQ（官方 OpenAPI）/ Telegram 适配器
  modules/account/ # 记账模块：规则解析、记账服务、平账、导入、查询、统计
  modules/admin/   # 管理模块：登录会话、配置加密、设置、备份、导出
  router.py        # 机长：意图路由与分发
  scheduler.py     # 提醒与热备份调度
  db.py            # SQLite（WAL）+ 迁移 + 热备份
  security.py      # scrypt 密码哈希 + Fernet 密钥加密
  main.py          # FastAPI 入口与统一入站协议
  static/admin.html
scripts/           # LF 校验、批量测试、服务器自测
tests/             # pytest 测试套件
docs/              # 部署、QQ 接入、导入说明
```
